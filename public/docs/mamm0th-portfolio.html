08 — AI Considerations

How AI Works Here

Model Stack

GPT-4o + Embeddings

GPT-4o for priority generation & RAG chat. text-embedding-3-small for transaction vectors stored in pgvector.

Why AI

Rules Can't Generalize

Patterns are industry-specific. A Tuesday dip means something different for sushi vs. boutique retail. LLMs reason across context; rules don't.

Build vs. Buy

OpenAI API for MVP

Fine-tuning only considered if output quality regresses at scale. Structured outputs (JSON mode) enforce schema without post-processing.

Failure Modes

Hallucinated Numbers

Risk: AI cites revenue figures not in the DB. Mitigation: all revenue claims must reference actual DB rows; RAG context injected per query.

Guardrails

Grounded Claims Only

Every priority references a transaction pattern. Fallback: "Check with your accountant for precise figures." Generic advice blocked by prompt constraint.

Responsible AI

Transparency + Privacy

Merchants informed all priorities are AI-generated. Square data used only for their own analysis. No cross-merchant data leakage — RLS enforced at DB level.

09 — Engineering

Technical
Decisions

As PM-Engineer, architectural choices were made with product outcomes — not just engineering taste — as the primary constraint.

  • Inngest over raw cron
    Background jobs need retries, observability, and fan-out for parallel embedding tasks. Inngest provides all three with zero infra overhead. Raw cron would require a separate worker process and blind failure handling — unacceptable for a weekly job merchants rely on.
  • pgvector not Pinecone
    Zero additional infrastructure, familiar SQL queries, Supabase already in stack. At SMB scale (~90 days × 1 merchant = ~2,700 transactions), a dedicated vector DB would be premature optimization. Revisit at 10K+ merchants.
  • Lazy singleton clients
    Next.js App Router initializes module-level code at build time — OpenAI and supabaseAdmin clients must be deferred. Proxy pattern wraps client creation in a getter so callers use normal syntax with zero build-time errors.
  • Streaming chat responses
    Multi-sentence RAG answers take 2–4s at GPT-4o. Streaming starts the first token at ~400ms, reducing perceived latency by ~80% — measurably improves trust that the system is working.
